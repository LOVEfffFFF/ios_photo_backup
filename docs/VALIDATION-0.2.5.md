# 0.2.5 原编辑时间保留实验

本版增加六个受限的时间保留实验，详见 [实验范围与验收](TIMESTAMP-EXPERIMENTS-0.2.5.md)。普通恢复继续使用原路径。六项实验现已在 iPhone 14 Pro Max / iOS 17.7.2 完成，均未保住实际编辑附件中的原编辑时间，不能称为已修复。

实验只接受手机当前连接中选定、已备份且具有当前编辑与渲染图的静态照片。每个任务最多创建一份新副本，原照片和备份内容不改动。严格资源校验、拍摄时间回读、完整 plist 导出和十次上限仍生效；前三层分别拒绝未知实验、旧版本手机及未授权的导入。网络重试只重送结果，不重做导入。

部分实验使用非公开 Photos 时间设置，仅供个人侧载真机排查；公开文档没有保证这些设置的稳定性或恢复效果。它们不在普通恢复流程启用，也未作为已验证修复推广。

## 2026-10-19 真机结果

用户覆盖安装后开启实时调试。六项实验依次执行：五项各创建一份副本，一项数据导入被系统以 `PHPhotosErrorDomain 3300` 拒绝。没有候选通过原编辑时间和完整附件的严格校验。

五份成功导入的副本均保持原 DNG、渲染图、压缩配方和完整解压 JSON 的字节一致，拍摄时间保留；实际导出的 plist 仍只有 `adjustmentTimestamp` 被改为拍摄时间。逐份独立解码、校验实际附件哈希后，仅替换原附件中的这个日期即可得到副本的完整字节。

`requestModificationDate` 和 `combinedDates` 将资产数据库的 `modificationDate` 设置成了原 plist 的秒级编辑时刻，但没有保住 plist 内的 `adjustmentTimestamp`，也没有恢复原数据库时间的小数部分。前者副本在任务结束后再次独立读取，数据库时间与附件时间仍保持这个差异，不能将数据库时间设置有效视为附件时间已修复。

所有原照片及电脑备份保留，五份测试副本未自动删除。没有对最新五份副本操作系统相册编辑界面，此前用户对旧副本的 RAW、还原和继续编辑验收不能代替本轮界面验收。实验尚未成为普通恢复功能，本轮没有生成新 IPA，仍只保留已验证的 0.2.5 包。

只有副本实际回读的编辑时间和完整附件正确，且原图、渲染图、完整配方与拍摄时间均保留，才能接受为候选修复。候选通过后还需独立回读、重复验证及系统相册功能验收。上述结果仅覆盖本设备、系统和所选样本；不能据此断言所有 iOS 版本都无法实现。
